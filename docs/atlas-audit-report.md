# Skyrim 1.7.104 Atlas audit

Read-only source audit, 2026-10-01. Findings are ranked by likely player impact within each verification section. `Verified: yes` means I also read the indicated function in `C:\Tools\skyrim_re\sk.cmd fn`; `no` means the engine conclusion is the Atlas's claim, although the cited client path was inspected. None of the proposed changes was built or exercised in game. The source tree already contains fixes for two incidents below; this report does not call them game-verified.

## Verified against the decompiled executable

1. **Replicated stages run local fragments — desync.** Mod: `Code/client/Services/Generic/QuestService.cpp:290-309`. Atlas: Q1/Q2, catalog `quest.stage.set` and `quest.fragment.dispatch`: `SetStage` N25004 (VA `0x1403D0DC0`) calls runner N25252 (`0x1403E19B0`), which posts the event handled by SkyrimVM sink N53987 (`0x1409DE4C0`). `ScopedQuestOverride` permits the setter; it does not suppress the fragment. Gate the VM fragment dispatch for host-owned replicated stages while completing the stage-item callback, then replicate objective state separately. Confidence: high. Verified: yes, `id:25004`, `id:25252`, `id:53987` and their decompiled bodies.

2. **Stage hook misses startup and shutdown fragments — desync.** Mod: `Code/client/Games/Skyrim/Forms/TESQuest.cpp:16-73,225-227`. Atlas: Q1, `quest.stage.set`: RunStartUpStages N25000 (VA `0x1403D0B20`) and RunShutDownStages N25001 (`0x1403D0BB0`) call N25252 without passing the hooked N25004. Gate at the runner or fragment sink with a quest/stage authority key, including lifecycle stages. Confidence: high. Verified: yes, `sk.cmd fn id:25000`, `id:25001`, `id:25252`.

3. **Follower quest alias fills may disappear from its save — desync.** Mod: `Code/client/Services/Generic/QuestService.cpp:496-534`. Atlas: Q3, catalog `quest.alias.force`; ForceRefIntoAlias N25052 (VA `0x1403D4FA0`) does not mark `kQuestRuntimeData`; FillAliases N25048 (`0x1403D3D10`) exits if any alias is already filled. The apply loop forces/clears aliases without `AddChange(0x10000000)`. Record that flag after a complete host fill, and preserve optional/unfilled aliases; test a save/load. Confidence: high for missing flag, medium for observed save loss. Verified: yes, `sk.cmd fn id:25052`, `id:25048`.

4. **Pending-door hook does synchronous activation and logging in an actor job — crash/deadlock.** Mod: `Code/client/Games/Skyrim/TESObjectREFR.cpp:145-174`. Atlas: P2/P3/P5, catalog `activation.anim_done`; runner N39408 (VA `0x1406F6E40`) runs in package tick N39637 on DynamicActorUpdate workers and from process demotions. The hook calls ActivateRef N19796 and can log while activation holds its global lock; it retains `apProcess`/`apActor` across a call that may unload them. Keep the native handle lifetime behavior, but marshal the stateful replay/diagnostic work to a safe phase and re-resolve the actor/process after activation. Confidence: high for thread and stale pointer risk, medium for an actual deadlock. Verified: yes, `sk.cmd fn id:39408`; worker ancestry is Atlas static tracing.

5. **Activation hook calls application services inside the engine activation lock — crash/perf.** Mod: `Code/client/Games/Skyrim/TESObjectREFR.cpp:1123-1154`. Atlas: activation A1, catalog `activation.begin`; ActivateRef N19796 (VA `0x1402F11B0`) holds a global reentrant spin lock through `base->Activate`. The hook synchronously calls three hold services, looks up world state, and triggers a network event. Capture a minimal immutable activation record and defer application/network work until after the lock; retain the pre-default semantic separately. Confidence: high for lock occupancy, medium for deadlock. Verified: yes, `sk.cmd fn id:19796`.

6. **Replayed door activation can travel or fire scripts twice — visible bug/desync.** Mod: `Code/client/Services/Generic/ObjectService.cpp:5945-5964`. Atlas: activation A1/A3/A4, catalog `door.open_state`; N19796 (`0x1402F11B0`) posts OnActivate before default processing; load-door travel begins after N14285 (`0x1401D99B0`) completes the opening. `pObject->Activate(..., defaultProcessing=0)` reproduces a full activation. Replicate door open state with SetOpenState N14287 (`0x1401D9EB0`) and snap where appropriate; reserve activation replay for interactions whose side effects are explicitly owned. Confidence: high. Verified: yes, `sk.cmd fn id:19796`, `id:14287`.

7. **Calendar resumes from stale raw days after disconnect — visible bug/desync.** Mod: `Code/client/Services/Generic/CalendarService.cpp:50-55,72-114`. Atlas: weather W3; Calendar::Update N36291 (VA `0x140645D60`) writes GameDaysPassed from `GameHour/24 + Calendar+0x3C`. The service advances `GameDaysPassed` directly while it blocks native ticks, but never updates `+0x3C` before re-enabling. Reconcile rawDaysPassed on disconnect, following load's N36317 (`0x140646BB0`), and test midnight and rejoin. Confidence: high. Verified: yes, `sk.cmd fn id:36291`.

8. **Weather blend percent write is overwritten by Sky::Update — visible bug.** Mod: `Code/client/Services/Generic/WeatherService.cpp:150-163`. Atlas: weather W2/W8; UpdateWeather N26231 (VA `0x140412810`) recalculates `Sky+0x1B8` from game time and `+0x1B4`, and ForceWeather resets clouds/precipitation. Apply the host's current/last weather and derived transition start time before Sky::Update, leaving `+0x1B8` to the engine; measure blend parity. Confidence: high for overwrite, medium for visible frequency. Verified: yes, `sk.cmd fn id:26231`.

14. **The pending-door field is HighProcessData, not MiddleHigh — cleanup with crash risk.** Mod: `Code/client/Games/Skyrim/TESObjectREFR.cpp:137-169`, `Code/client/Services/Generic/DoorVoteService.cpp:84-100`. 15. **Opt-in furniture repair uses the wrong dependent-link flag and races the manager — visible bug/crash.** Mod: `Code/client/Services/Generic/FurnitureGraphLink.cpp:36-58,87-137`. Atlas: A4/H3/P9, `anim.graph.dependent_link`; N63364 (VA `0x140BC0E60`) is called by native seating N39912 (`0x1407246A0`) with flag **1**, which binds actor channels into furniture. Verified: yes, `sk.cmd fn id:39912` shows the flag-1 call; `id:63364` is a thunk.

16. **Quest Kill is a latent pointer/flag corruption trap — cleanup/crash.** Mod: `Code/client/Games/Skyrim/Forms/TESQuest.cpp:172-184`, `TESQuest.h:182`. Verified: yes, `sk.cmd fn id:25003` and source call search.

## Corrections, boundaries and research notes

- **Atlas error found in older text:** the assertion that MQ101DragonAttack stage 105 is a fallback is wrong. `C:\Tools\skyrim_re\agent\FINDINGS.md:27-29` identifies scene `SF_MQ101DragonAttackScene1` Fragment_16 as its independent source; a `50 -> 105` trace still proves only that 103 was absent before scene progress. The Atlas's current A1-A6 wording does not depend on 105 being a fallback.
- **Independent-review disagreement resolved against the executable:** Reviewer A suggested the mod's bit-only `TESQuest::SetStopped` skips native shutdown. The Atlas quest-scene-alias §9 and `sk.cmd fn id:24987` show native N24987 itself only clears kEnabled and marks change 2; BGSStoryTeller later runs shutdown stages and cleanup. `QuestService::StopQuest` additionally calls `SetActive(false)`. The suggested stop-path finding was rejected. Reviewer A correctly downgraded `TESQuest::Kill`: it is not called in current client code.
- **Corrected Atlas claims retained:** S8 relinks also run when N35567 processes queued change forms outside a save load; they do **not** run for arbitrary network changes or plain 3D rebuilds. This matters for furniture dependent links N39432/N40064, ExtraData dependent links N12843, and open/navmesh restoration N19531. Q1's no-fragment route must still complete the stage-item callback; simply dropping the event can strand a latent stack or a quest in Starting. The catalog's `EnableFunctor` `thread: main` label is contradicted by `ANSWERS` jobs/threading: it runs in Job_Post_process on a worker in running frames.
- **No supported wrong-size finding:** Atlas memory §4 confirms the mod's `sizeof(Actor)==0x2B8` and `sizeof(PlayerCharacter)==0xBF0` assertions. Atlas S10 says flattened CommonLib PlayerCharacter offsets are eight bytes early for 1.7.104, but this client does not use the cited flattened CommonLib runtime members at the reported sites. `AIProcess+0x10` pending-door offsets are correct; the names are wrong. I found no other client `POINTER_SKYRIMSE` numeric ID contradicted by a named Atlas entry; this is a cross-reference audit, not an independent ABI proof for every one of the roughly 600 uses.
- **Paths not falsely flagged:** `CharacterSnapshots.cpp:225-246` checks perk ownership before calling AddPerk/RemovePerk on the local player, consistent with Atlas PERK3's duplicate-entry warning. `PlayerService.cpp:103-130` writes two `TESGlobal::f` values at connection boundaries for session policy; these are deliberate local toggles, not a network global-replication channel. `WorldStateService` applies durable reference state through native paths, so I found no supported raw `ExtraAction` open-bit or quest-stage done-bit write in that service. These observations do not establish save persistence for any future global replication.
- **Save-load replay gap:** synchronize furniture seating through N37325/N39912, dependent graph links through N63364 with flag 1, door open state through N14287 (snap for obstacle parity), and animation registrations by unregister/re-register after graph rebuild. `Actor::FinishLoadGame` N37652 and `TESObjectREFR::FinishLoadGame` N19531 are load hooks, not a general network apply API. See `ANSWERS` S8/A4 and catalog `furniture.enter`, `anim.graph.dependent_link`, `door.open_state`.
- **Cheap replacements for guesses:** catalog `player.controls` gives the live/stored mask offsets and mask semantics; `tables/change_flags.tsv` gives persistence bits and native setters; `tables/task_codes.tsv` gives save/door task codes; `graph/ai_process_field_writers.tsv` identifies High `+0xD8/+0x470` writers and their job ancestry; catalog `cell.attach` provides the attach event source. Use these before adding counters or raw offsets.
- **Primary-source precedent inspected:** [CommonLibSSE AIProcess implementation](https://github.com/libxse/commonlibsse/blob/main/src/RE/A/AIProcess.cpp) confirms the high versus middleHigh distinction and native 3D update seam; [CommonLibSSE-NG HighProcessData definition](https://ng.commonlib.dev/_high_process_data_8h_source.html) provides the typed comparison. The [Skyrim Together Reborn source tree](https://github.com/AHilyard/SkyrimTogetherReborn) establishes this fork's prior client/encoding/server design; its feature descriptions alone were not used as engine evidence. The installed 1.7.104 executable and Atlas corrected reviews take precedence over older CommonLib layouts.
- **Independent review:** Reviewer A (local Claude) completed a read-only pass and suggested the stage-hook alias race and recent-autosave checkpoint finding. Reviewer B (local Muse) could not start in this sandbox: its launcher attempted to write an update marker outside the workspace and received access denied. Reviewer A's native-shutdown concern was rejected above after executable inspection. Neither assistant's agreement is used as validation. No protocol tests, profiling, build or paired game session was run for this report; five-player performance and in-game closure remain unmeasured.
