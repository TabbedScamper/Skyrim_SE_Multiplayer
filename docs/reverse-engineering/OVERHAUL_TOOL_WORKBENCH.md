Shallow clones are under `C:\Users\mwalt\SkyrimResearch\`; no proprietary assets or downloaded executables were added to this repository. ## First integrated result: Address Library v5 manifest

The toolkit's `mine_function_ids.py` rejected the installed file because it supports only Address Library formats 1/2; the installed `versionlib-1-7-104-0.bin` is **format 5**. [Our existing native v5 loader](../../Code/client/VersionDb.h) defines the layout. [Build-FunctionManifest.py](../../Tools/EngineAtlas/Build-FunctionManifest.py) adds a read-only v5 parser and reuses the toolkit's CommonLib symbol miner, with strict file-size, module-name and version checks. Run it with the pinned toolkit script directory, pinned CommonLib root and commit, installed versionlib/EXE paths, and an output path outside the game and repository. [Three synthetic parser tests](../../Tools/EngineAtlas/test_build_function_manifest.py) pass.

The generated **private** artifact is `C:\Users\mwalt\SkyrimResearch\symbols-1-7-104.json` (not committed). It binds EXE SHA-256 `846EFCCF0C1374D71F892907F46549560F2FCB0A75CB87A3EED438BAA0F1402F` to Address Library SHA-256 `8AAB3DD251D135B849BD983F86A4A205C920FA3E81F8E30C0E63CCFEF9423842` and CommonLib pin `b93280e832f263dbef44e44cbe2936622a02f91a`. It read 565,759 ID slots (435,162 nonzero RVAs), scanned 2,043 CommonLib files, and emitted 15,220 candidate labels; 1,354 mined symbols were unresolved and 11 IDs have multiple names. For example, candidate `AIProcess::GetHeadtrackTarget` ID `39484` maps to RVA `0x6FF050`, which is near the earlier `+0x6FF05A` crash site; this **does not** prove a correct signature, receiver, or safe call phase. ID `36544` remains a documented conflicting label (`Main::Update` versus `winMain`) and was not resolved by this miner. Before hooking, validate candidate boundaries, callers, ABI and live receiver state in the exact EXE.

The independent reviews agreed the v5 function manifest and authored HKX graph manifest are the next high-leverage tools. Reviewer A favored serde-hkx's CLI/verification flow; Reviewer B favored HKX2Library's explicit Skyrim class model and Pandora's patch provenance. We retain both parsers for a disagreement report. Reviewer B suggested a future isolated Pandora patch trial, but that would not by itself explain live host/follower pose parity; the first experiment remains read-only graph extraction and comparison.

## Next integration gate (in order)

1. **Freeze identity:** record executable and Address Library hashes, plugin order/version/hash, and chosen parser commit for each artifact. Distinguish plugin FormKeys, live reference IDs, network entity IDs, Address Library IDs, Havok class names and animation clip IDs; they are different namespaces.
2. **Offline authored-state oracle:** extract locally owned MQ101 records and relevant HKX into a private analysis directory. Compare xEdit/Mutagen quest, scene, condition and alias output; compare serde-hkx/HKX2 graph topology. Publish only derived counts, hashes, relationships and parser mismatch reports—not game assets.
3. **Bounded live decision trace:** for a selected actor on both PCs, record host tick/ownership epoch, active scene action, AI package and target, graph state/input checksum, clip activation/variant, evaluated pose and final render-node checksum. Align by source tick and graph phase, not wall-clock screenshots. OAR and PapyrusProfiler inform possible hook points, but every 1.7.104 hook must be validated independently.
4. **Causal replay:** first failing same-tick field determines the next patch. If authored data differs, fix mod parity; if scene/package/clip choice differs, move that decision under host authority; if only evaluated/final pose differs, investigate solver/attachment or a single final presentation writer. Keep cart rigid-body state and save change forms as separate authority domains. No five-player performance claim until measured.

No cloned tool was executed against game data in this pass. No runtime parity or crash fix is claimed.
