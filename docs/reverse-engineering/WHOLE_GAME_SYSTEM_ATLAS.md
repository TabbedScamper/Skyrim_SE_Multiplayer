# Whole-game co-op system atlas (research, 2026-09-24)

Scope: Skyrim SE 1.7.104, this fork, and source-visible public mods. This is a map of *observation and authority boundaries*, not proof that every system can be synchronized from one hook. No third-party DLL was installed or game session changed. The exact-EXE ABI gate in [Engine Atlas](../../Tools/EngineAtlas/README.md) applies to every native reference below.

## Source adoption boundaries

- Read these projects as *specific subsystem references*, not a merged replacement engine. `Precision` and `SSE Display Tweaks` are especially useful for Havok timing/collision, but neither implements shared-world authority. `QuickLootIE` clarifies pre-take transaction and dropped-reference identity, not anti-duplication. `AudioUtil` demonstrates playback and lip-sync controls, not synchronized dialogue timing.
- Do not copy third-party hooks/offsets into 1.7.104 unchanged. Some sources target other Skyrim runtimes; open-source availability does not establish binary compatibility. Respect each project's license before copying code.
- Source inspection also exposed a subtitle relay omission: `SubtitleRequest` and `NotifySubtitle` both carry `TopicFormId`, but `server/Services/CharacterService.cpp::OnSubtitleRequest` copies only server ID, tick and text. This is a concrete serialization/relay gap, not yet an observed in-game subtitle mismatch. A paired test and server relay unit test should precede a fix claim.
- A universal synchronization design needs a per-domain host transaction/decision ledger, stable entity/asset identity, source-tick phase alignment, and a follower presentation policy. Rendering, user-local menus/options and audio output device should not be forced to be bit-identical merely because shared game state is authoritative.

## Priority experiments

1. One dropped-item transaction plus simultaneous container pickup: this directly tests missing world-reference creation and duplication.
2. One selected NPC death/ragdoll and one loose object collision: compare pre-step, post-step, graph output and final render, never all bones at once.
3. A synthetic health-delta protocol test first: positive heal and negative damage must move server/client health in the same direction; reject unowned/stale-epoch messages. Then paired-test one combat hit, non-concentration spell and shout through intent -> projectile/contact -> damage/effect -> audiovisual result, keyed by host event ID.
4. One load/cell transition with an open menu and dialogue: compare game-ready, UI focus/pause and voice/subtitle timing without assuming the two PCs finish loading simultaneously.
